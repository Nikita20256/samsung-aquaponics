ИЗМЕНЕНИЯ В ПРОЕКТЕ
Дата: 16 октября 2026 года

Цель обновления
Проект переведён с Expo SDK 54 на SDK 57, чтобы устранить несовместимость
с установленным на телефоне Expo Go для SDK 57.

1. Файл package.json

Обновлены зависимости:
- Expo: 54.0.37 -> ~57.0.30 (установлена версия 57.0.30).
- React: 19.1.0 -> 19.2.3.
- React Native: 0.81.5 -> 0.86.3.
- Типы React (@types/react): 19.1.17 -> ~19.2.2
  (установлена версия 19.2.18).
- TypeScript: 5.9.3 -> ~6.0.3 (установлена версия 6.0.3).

Знак ~ разрешает исправления в пределах указанной минорной версии.
Точные установленные версии закреплены в package-lock.json.

Добавлены требования к Node.js в поле engines:
^20.19.4 || ^22.13.0 || ^24.3.0 || >=25.0.0.

Добавлена команда start:tunnel, которая выполняет expo start --tunnel.
Она запускает сервер разработки через интернет-туннель и может помочь,
если VPN мешает телефону подключаться к компьютеру по локальной сети.

2. Файл package-lock.json и установленные пакеты

Обновлён package-lock.json с точными версиями зависимостей SDK 57.
Командой npm install обновлены пакеты в папке node_modules.

3. Файл README.md

Обновлены сведения о версиях Expo, React и React Native.
Уточнены требования к Node.js и Expo Go.
Добавлены инструкция запуска через туннель при включённом VPN,
объяснение ошибки несовпадения SDK и результаты проверок после обновления.

4. Проверки после обновления

- npm run typecheck: успешно, ошибок TypeScript нет.
- npx expo-doctor@latest: пройдены все 21 проверки.
- npx expo install --check с EXPO_OFFLINE=1: версии соответствуют
  локальному списку совместимости SDK 57.
- npx expo export --platform all --output-dir dist: успешно созданы
  JavaScript-бандлы Android и iOS с компиляцией Hermes в папке dist.
  Это проверка бандлов, а не создание установочных APK или IPA.

Запуск на физическом телефоне и подключение через VPN ещё не проверены.

npm audit сообщил о 22 уязвимостях в цепочках зависимостей:
7 уровня moderate и 15 уровня high.
Принудительное исправление через npm audit fix --force не выполнялось:
среди предлагаемых изменений есть несовместимый откат Expo/React Native.

5. Код и внешний вид приложения

App.tsx, index.ts, src/screens/WelcomeScreen.tsx, app.json и tsconfig.json
при этом обновлении не менялись. Приложение по-прежнему показывает
надпись «Привет» по центру светлого экрана.

6. Как запустить после обновления

Откройте терминал в папке проекта. Если старый сервер ещё работает,
остановите его сочетанием Ctrl+C. Затем выполните:

npm run start:tunnel

Пакет @expo/ngrok теперь установлен локально в проекте (см. пункт 7).
Отсканируйте новый QR-код в Expo Go для SDK 57 на телефоне.
VPN можно оставить включённым, если он разрешает доступ к туннелю.

Обычный запуск по локальной сети:
npm start

Для повторной установки зависимостей из package-lock.json:
npm ci

7. Исправление ошибки установки ngrok

После обновления обнаружилась ошибка:
CommandError: Install @expo/ngrok@^4.1.0 and try again.

Проверка показала, что глобальный @expo/ngrok установлен, но механизм
поиска глобальных модулей Expo CLI его не находит.

В devDependencies файла package.json добавлен @expo/ngrok: ^4.1.3.
Обновлены package-lock.json и установленные пакеты.
Проверено через NgrokResolver из Expo CLI: локальный пакет версии 4.1.3
находится и загружается, функция connect доступна.
Это устраняет ошибку поиска пакета. Доступность сервиса туннеля через VPN
и запуск на телефоне этой проверкой не проверялись.

README.md дополнен описанием исправления. Глобальная установка ngrok
больше не требуется: при npm ci устанавливается локальная зависимость.
После добавления ngrok npm сообщил о 23 уязвимостях в цепочках
зависимостей: 8 moderate и 15 high (вместо прежних 22).
